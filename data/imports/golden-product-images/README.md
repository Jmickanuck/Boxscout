# Supervised image import — local pilot

The manifest is an offline, reusable candidate/review queue. Current assets: zero. discovery.json retains one unassigned official promotional URL, not a verified base image. Unknown rights never authorize downloading a file. Keep private evidence/contracts outside Git; commit only public-safe summaries/references.

1. Discover a reference and establish the canonical card ID/release/side; leave ambiguous observations unassigned in discovery metadata. Add a manifest asset only when its proposed target is known. Multiple candidates are allowed. Do not infer parallel identity from player name.
2. Fill ImageAsset fields defined in src/types/images.ts. Record match and rights rationales independently. All booleans/nullable fields are explicit. Candidate assets use isPrimary:false and input:null when there is no permission to persist a file.
3. Only after sufficient permission, provide a local input in an ignored .image-inputs directory (or pass --input-dir=PATH). Use a plain filename and SHA-256. APPROVED requires VERIFIED match, PUBLIC_ALLOWED, dated reviewer, grant evidence and publicWeb/derivatives/repositoryDistribution all true. Expiring grants are unsupported for this static pilot. Permission must permit the page-level credit placement. Do not remove watermarks or alter card art.
4. Set one approved primary per card/variant/side. The CLI currently loads Golden Product canonical targets; the shared validator/generator accepts another target list without product-specific matching logic. A future adapter may supply those targets without duplicating the pipeline. No network fetch occurs in generation.
5. Run npm run images:generate, then npm run images:check. Build checks verify public output bytes, metadata, rights and recorded input hashes without requiring private/ignored inputs on Vercel. For full local byte replay against retained permitted inputs, run npm run images:generate -- --replay. Output: bounded <=800×1120 WebP masters (<=200 KB each) and a public typed sidecar. Next.js delivers smaller responsive derivatives. Inputs are decoded with pixel/byte limits, oriented and stripped of EXIF/GPS. Known input metadata is checked; hashing detects changed sources. Recipe pins Sharp 0.35.4; compare byte replay on the actual platform, not an assumed cross-platform promise.
6. Review every public file, generated projection and rights evidence. Generation fails if stale/unapproved files already exist. Remove only the specifically reviewed stale files; then regenerate, deploy and verify caches/old deployments for withdrawal. Never force-push to erase history. Do not treat UI fallback as deletion of a public asset.

public/ is a publication boundary. Never put an input there for convenience. Raw candidates/review metadata do not enter client payloads. Missing/back-only/variant-only images do not replace a base front. Tests generate synthetic pixels in a disposable OS temp directory and verify the positive path without shipping invented card art.

No paid storage, crawler, admin UI, account or future product implementation is authorized here. Future image/evidence storage requires a separate backup/restore strategy; GitHub is not a database/object-store backup.
